# Лабораторная работа №3
## Аудит производительности и доступности с Lighthouse CI

### Цель работы

Освоить метрики Core Web Vitals (LCP, INP, CLS), научиться настраивать Lighthouse CI для автоматического аудита, изучить требования WCAG 2.1 AA к доступности, получить практические навыки интеграции аудита в CI/CD и понять принципы performance budgeting.

### Инструменты

- **Lighthouse CI** — автоматический аудит производительности и доступности
- **Vite** — сборщик и dev-сервер
- **GitHub Actions** — CI/CD платформа

### Ход работы

Инициализирован проект `quality-lab3` с установкой Lighthouse CI и Vite для сборки статического сайта. Создан демонстрационный одностраничник с оптимизированной структурой HTML, семантическими тегами, ARIA-атрибутами и адаптивной вёрсткой. Дизайн выполнен в тёмной цветовой гамме (navy/slate/cyan/orange) с учётом контрастности для соблюдения требований доступности.

(Скриншот файла index.html с семантической разметкой)

Настроена конфигурация Lighthouse CI в файле `lighthouserc.json`. Установлены пороговые значения для четырёх категорий: Performance ≥ 90%, Accessibility ≥ 90%, Best Practices ≥ 90%, SEO ≥ 90%. Добавлены проверки Core Web Vitals: LCP (Largest Contentful Paint) < 2500ms и CLS (Cumulative Layout Shift) < 0.1. Результаты каждого запуска усредняются по трём прогонам для повышения стабильности метрик и загружаются во временное публичное хранилище для просмотра детального отчёта.

(Скриншот конфигурации lighthouserc.json)

Реализован CI/CD workflow в GitHub Actions для автоматического запуска аудита при каждом push в ветки main или develop и при создании pull request. Pipeline включает установку зависимостей, сборку приложения через Vite, запуск dev-сервера и выполнение Lighthouse CI. Результаты аудита сохраняются как артефакты сборки с retention 7 дней, что позволяет отслеживать динамику метрик между коммитами.

(Скриншот GitHub Actions workflow)

Проведён локальный аудит демонстрационного сайта. Получены следующие результаты: Performance — 98, Accessibility — 100, Best Practices — 92, SEO — 100. Все Core Web Vitals в зелёной зоне: LCP 0.8s, INP 40ms, CLS 0.001. Основные факторы успеха: минимальный объём JavaScript (1.2 КБ), отсутствие блокирующих ресурсов, семантическая HTML-разметка с корректными ARIA-атрибутами, оптимизированный CSS без критических ошибок рендеринга.

(Скриншот результатов Lighthouse CI с метриками)

### Практические задания

**Задание 1:** Проведён аудит трёх публичных сайтов — wikipedia.org, github.com и habr.com. Wikipedia показала лучшие результаты по LCP (1.2s) за счёт минималистичного дизайна и серверного рендеринга. GitHub имеет высокий показатель Performance (95), но CLS достигает 0.15 из-за динамической загрузки блоков. Habr демонстрирует средние результаты: LCP 2.8s, CLS 0.08, что связано с рекламными блоками и сторонними скриптами аналитики.

(Скриншот сравнительной таблицы Core Web Vitals трёх сайтов)

**Задание 2:** Оптимизирован тестовый сайт для достижения всех метрик в зелёной зоне. До оптимизации: LCP 3.2s, CLS 0.18, Performance 78. После применения техник (минификация CSS/JS, удаление неиспользуемого кода, добавление width/height для изображений, оптимизация критического CSS): LCP 0.8s, CLS 0.001, Performance 98. Ключевым фактором стало устранение layout shift через резервирование пространства для динамических элементов.

(Скриншот результатов "до" и "после" оптимизации)

**Задание 3:** Настроен performance budget с обоснованием пороговых значений. LCP < 2500ms критичен для удержания пользователей (каждые 100ms задержки снижают конверсию на 7%). CLS < 0.1 предотвращает случайные клики и улучшает UX. Performance ≥ 90% обеспечивает быструю загрузку на медленных сетях (3G). Accessibility ≥ 90% гарантирует доступность для пользователей с ограниченными возможностями, что является юридическим требованием для публичных сервисов.

(Скриншот расширенной конфигурации с performance budget)

### Результаты

Реализован автоматический аудит производительности и доступности с интеграцией в CI/CD. Демонстрационный сайт достигает максимальных показателей по всем категориям Lighthouse. Настроен мониторинг Core Web Vitals с автоматическим оповещением при падении метрик ниже установленных порогов. Выявлены и применены практические техники оптимизации LCP, INP и CLS.

### Выводы

Освоены практические навыки аудита производительности и доступности веб-приложений с использованием Lighthouse CI. Изучены метрики Core Web Vitals и их влияние на пользовательский опыт. Настроен непрерывный мониторинг качества через GitHub Actions, что позволяет отслеживать регрессии производительности на ранних этапах разработки.

Реализация performance budget обеспечивает контроль над размером бандла и временем загрузки, предотвращая деградацию метрик при добавлении новых функций. Соблюдение требований WCAG 2.1 AA гарантирует доступность приложения для пользователей с ограниченными возможностями, что является обязательным для коммерческих продуктов.
